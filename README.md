# PPE Script Style Engine — Claude Code Setup

This is the engine we built in chat: a SQLite database + Python scripts that
ingest video scripts, build "style profile" fingerprints per channel, and
score new inputs against them (pre-creation) or rewrite them into a target
style and re-score (post-creation).

You don't need to know Python to run this — Claude Code can run everything
for you if you just describe what you want in plain English. This file is
mainly so *you* know what's possible to ask for.

## 1. Open this folder in Claude Code

Unzip `ppe_engine.zip` somewhere (e.g. Desktop or Documents), then open
Claude Code and point it at that folder — either via `cd` to the folder
before launching, or through Claude Code's "open folder" option.

## 2. First thing to ask Claude Code

> "Read README.md in this project, then check my Python environment has
> pandas and openpyxl installed. Install anything missing."

Claude Code will run `pip install pandas openpyxl --break-system-packages`
(or similar) if needed. The database (`db/ppe_engine.db`) already exists
and already has three channels ingested with confirmed profiles —
Philosophyminis (A.1), fryrsquared/Hannah Fry (A.2), and robdwillis (A.3) —
you don't need to redo that part.

## 3. Or just use the browser interface

There's a local web app (`scripts/webapp.py`) that wraps all the scripts
below in a browser UI:

- **Workflow** — the guided path: Input (paste text or upload a .txt/.srt/.vtt
  media file) → Choose Profile Style (short band A vs long band B, with
  pre-creation scores shown per profile) → Output (generate the rewrite
  prompt, paste back the result, see the before/after score delta).
- **Dashboard** — engine overview with the workflow diagram front and center.
- **Inputs** — browse the training corpus (every ingested video), filterable
  by channel, title, title format, and word-count range, with a detail page
  per video showing the full script and every extracted attribute. You can
  jump straight from a corpus video into the Workflow to score it.
- **Creations** — browse every rewrite generated by the Workflow/Transform
  step (the post-creation half), filterable by target profile, generated-by,
  min score delta, with a detail page showing the full generated script and
  its ranking against every profile.
- **Attributes** — the full catalog of all 63 stylistic attributes the engine
  tracks, grouped into 5 macro categories (Structure & Pacing, Voice &
  Diction, Rhetoric & Persuasion, Content & Delivery, Engagement & CTA) with
  a live coverage % per category up top, and every individual attribute
  listed below with its type, description, and live stats (range/mean for
  numeric, true/false split for boolean, distinct-value count for
  categorical) computed straight from the current corpus.
- **Profiles** / **Test History** — browse fingerprints and past scoring runs.
  Each profile page also shows the same 5 macro categories scoped to that
  profile: what share of each macro's attributes actually made it into
  *this* profile's fingerprint, vs. still needing classification (or not
  yet tracked by `profile_builder.py` at all — the boolean flags currently
  aren't rolled into any fingerprint). Each profile also links to three
  more pages (see section 7 below): **Style Card** (human-declared voice
  description + negative space, with a delta against the observed
  fingerprint), **Voice Drift** (snapshot the fingerprint and compare
  against a later point in time), and **Compare** (distance/similarity
  score against any other profile).
- **Score Text** / **Rewrite / Transform** — the original single-purpose
  pages, still there under "advanced" for direct access.

Run:

```
python3 scripts/webapp.py
```

then open http://127.0.0.1:5050. Everything it does is backed by the same
DB and scripts — it's just a friendlier way to drive the demo than the CLI.
(Needs Flask: `pip install flask --break-system-packages` if it's not
already on your machine.)

## 4. Things you can ask Claude Code to do

**Add a new channel's transcripts:**
> "I have a CSV with columns Title and Script for [channel name]. Ingest it
> using scripts/ingest.py, then build the style profile using
> scripts/profile_builder.py with code [A.2 / B.1 / etc]."

Your CSV just needs two columns: `Title`, `Script`. (Optional: `URL`,
`Duration`, `PostedAt`.)

**Check a profile's fingerprint:**
> "Show me the fingerprint for profile A.1 using profile_builder.py --show"

**Classify the subjective attributes (hook type, structure, etc.):**
> "Export the un-classified videos for Philosophyminis using
> classify_template.py --export, then classify them yourself against the
> rubric in the prompt, save the result as JSON, and merge it back in with
> --load."
(Claude Code can actually do the classification itself here, since it's an
LLM — this is the step that needs judgment, not just computation.)

**Rate a new piece of text (pre-creation):**
> "Score this script/paragraph/article against all our style profiles using
> score_engine.py — here's the text: [paste text]"

This tells you, per profile: is it an exact/near match to something already
in that profile's corpus (content match, scores ~100), or how well its
structure/diction correlates with that profile's style (attribute
correlation, scores based on where it falls in that profile's actual
observed range).

**Rewrite something into a target style, then check how well it worked
(post-creation):**
> "Take test_id [X] and rewrite it into profile A.1's style using
> transform.py — pull the fingerprint targets, write the new version
> yourself, save it, and score it against all profiles so I can see the
> delta vs. the original."

**Tune the scoring weights:**
> "Show me the scoring_weights table and let's adjust it so word_count and
> you_freq_per_100w matter more for the 1-minute Instagram band."

**Export everything to Excel to look at:**
> "Export every table in db/ppe_engine.db to one Excel workbook, one sheet
> per table, so I can open it directly."

## 5. Project structure

```
ppe_engine/
  db/
    schema.sql          -- table definitions
    ppe_engine.db        -- the actual database (146 Philosophyminis + 40
                             fryrsquared + 33 robdwillis videos loaded,
                             profiles A.1, A.2, A.3 already built)
  scripts/
    db_init.py           -- (re)creates the DB from schema.sql
    feature_extraction.py -- computes objective text stats (word count,
                              readability, "you"/"I" frequency, etc.)
    similarity.py         -- content-match / membership detection
    ingest.py             -- loads a Title+Script CSV into the DB
    classify_template.py  -- the rubric + merge logic for subjective
                              attributes (hook type, structure, etc.)
    profile_builder.py    -- rolls videos up into a channel's style
                              fingerprint
    score_engine.py        -- pre-creation rating (membership + attribute
                              correlation) against all profiles
    transform.py             -- post-creation: rewrite into a target style,
                              score the rewrite, compute the delta
    webapp.py                 -- Flask browser UI wrapping the above
    templates/                -- HTML templates for webapp.py
```

*Added building A.3 (robdwillis):*

  framework markers ("step one", "number two", "the third thing"...). This
  is the single clearest fingerprint of Rob's channel: his scripts average
  **0.88** markers each vs. **0.04** for Philosophyminis and ~0.1 for
  fryrsquared — auto-computed and backfilled onto **all 219** videos across
  all three channels the moment it was added, so it's already part of every
  profile's fingerprint.
- Enum extensions: `domain` gained `"Communication/Rhetoric"` (81.8% of
  A.3's videos landed there — the existing enum had no home for a
  communication-coaching channel), `explanation_mechanism` gained
  `"Case-study breakdown"` (51.5% of A.3, defined as the video's entire
  structure being a step-by-step analysis of one named person's real
  communication), and `concept_type` gained `"Practical framework/how-to"`
  for Rob's non-case-study advice videos (33.3% of A.3).
- New attribute *columns* are auto-computable, so they're backfilled onto
  the whole corpus for free. New *enum values* on existing columns (like
  `"Communication/Rhetoric"`) aren't retroactively applied to already-
  classified videos on other profiles — A.1/A.2's existing `domain`/
  `explanation_mechanism` values were classified before these values
  existed, so they won't use them even where they might arguably fit better
  now. That's a normal taxonomy-evolution gap, not a bug; re-running the
  classification pass on A.1/A.2 would let them use the fuller enum.
- Every macro card (Attributes page and each profile page) recomputes its
  attribute count and coverage % live — Structure & Pacing went from 21 to
  22 tracked attributes, and the totals shown everywhere reflect that
  automatically.

## 7. Attribute system refinement (gap analysis)

You handed over two lists — a 10-item "style card" spec and an 8-item list of
gaps in the attribute system — with instructions to add what's missing,
adapt what's already covered, and skip what doesn't genuinely help. Here's
the triage, with reasoning, followed by what got built.

### Style card (10 items)

| # | Item | Verdict | Where |
|---|---|---|---|
| 1 | Sentence rhythm | Already covered (`avg_sentence_len`, `median_sentence_len`, `sentence_len_variance`) — **added** `sentence_rhythm_cv` because raw variance scales with the mean and isn't fairly comparable across profiles with different average sentence lengths | Length & pacing |
| 2 | Paragraph shape | Only `beat_count` existed (a count, not a shape) — **added** `closing_paragraph_ratio` | Structure |
| 3 | Vocabulary | Only jargon/colloquialism density existed — **added** `lexical_diversity` (type-token ratio) | Diction |
| 4 | Opening habits | Already fully covered (`hook_type`, `hook_word_count`, `hook_names_source`, `hook_ends_on_pivot`, `hook_self_demonstrating`) — no change | Hook |
| 5 | Closing habits | Already fully covered (`close_type`, `ends_on_question`, `callback_to_hook`, CTA fields) — no change | Close |
| 6 | Additional media resource use | **Skipped** as literal video/audio extraction — this engine ingests transcribed text only, no video processing infrastructure. **Adapted** to a text-level proxy instead: `references_external_media` detects the script explicitly calling out another clip/video/footage | Structure |
| 7 | Punctuation | Only narrow counts existed (`emdash_count`, `quote_count`) — **added** `punctuation_density` | Diction |
| 8 | Formality | Conceptually covered by `script_polish`, but `colloquialism_density` was a dormant schema field that had never actually been computed by anything — **fixed** by implementing it | Diction |
| 9 | Humor | Not covered at all — **added** `humor_marker_count`, a coarse joke/exclamation-marker proxy. Explicitly *not* true humor detection (documented as such); a real "how funny is this" judgment would need classification, and this batch already added one new classified field (see below) | Delivery |
| 10 | Hashtag behavior | **Skipped** as an auto attribute — captions/hashtags were never part of the ingested corpus (the source spreadsheet has Title + Script only). **Adapted** into the new Style Card as a human-declared field instead, since a person can describe it even though the engine can't observe it | Style Card |

### Gaps list (8 items)

| # | Item | Verdict |
|---|---|---|
| A | Quantifiable style metrics (TTR, sentence length+variance, readability, punctuation density, 1st/2nd-person ratio) | Sentence length/variance/readability already existed. **Added** `lexical_diversity`, `punctuation_density`. First-vs-second-person ratio: **adapted**, not stored as a new column — `i_freq_per_100w` and `you_freq_per_100w` already exist side by side in every fingerprint, and a stored ratio would be fragile (division by zero whenever a video has no "you", and "mean of ratios" ≠ "ratio of means" at the profile level) |
| B | Topic/content-pillar vector | A true embedding is out of scope (no vector/ML infrastructure here). **Adapted**: `domain`/`concept_type`/`source_era`/`framing` categorical fingerprints already function as a coarse topic taxonomy per profile. **Added** a lightweight proxy on top: `named_entity_count` (who/what a script names) |
| C | Rhetorical pattern taxonomy (story/advice/opinion/question-led, hook pattern, CTA frequency, contrast structures) | Hook pattern and CTA frequency already covered. **Added** `rhetorical_mode` (classified: Story/Advice/Opinion/Question-led) and `contrast_structure_count` (auto: "X instead of Y" patterns) |
| D | Negative space as a tagged/diffable vector | Not covered at all — the engine had no concept of *declared* (as opposed to observed) profile data. **Added**: `profile_style_card` table supports tagged `banned_word`/`banned_tone`/`banned_format` constraints per profile, editable from the new Style Card page |
| E | Voice drift over time | Not covered — no snapshot mechanism existed, and no video in the corpus has a real `posted_at` date to bucket by time anyway. **Added** `profile_fingerprint_snapshots` — take a labeled snapshot now, come back later, and diff against current. A "baseline" snapshot was taken for all three profiles so the mechanism is ready; there's no real historical drift to show yet since this is the first snapshot |
| F | Declared-vs-observed delta as a scored attribute | Not covered — same root gap as D (no declared-data concept existed). **Added** as part of the Style Card: for the six style-card fields that map to a real fingerprint metric (sentence rhythm, paragraph shape, vocabulary, punctuation, formality, humor), declaring a plain number computes a live delta against the observed fingerprint mean |
| G | Cross-platform consistency | **Skipped** the specific feature — none of the three current profiles have a second platform's data to test against, and fabricating one would be dishonest. **Built the general mechanism it would use instead**: a profile-to-profile similarity/distance score (`/profiles/compare`), numeric attributes compared by relative difference, categorical by distribution overlap. This is also the direct answer to gap A's "distance/similarity between profiles" ask. Apply it to two platform-variant profiles once that data exists |
| H | Engagement-attribute correlation | **Skipped**, fully — verified the source spreadsheet's "Rating" column is 98.6% empty (217/220 blank) and isn't performance data anyway (it's a manual 1–5 quality rating, not views/likes). No engagement/performance data exists anywhere in this corpus. Building a correlation feature with nothing to correlate against would just be dead code. If per-video view/like counts become available, add a `videos.engagement_score` column and this becomes straightforward to build against the existing fingerprint infrastructure |
